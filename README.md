# 股票 · 趋势波段（个人自用 · 本地优先）

按《[技术需求书-股票App.md](技术需求书-股票App.md)》v0.3 实现。定位：**A 股 / 美股 · 日线 · 趋势波段（3~20 个交易日）**的选股、验证与持仓管理工具（两个市场数据、参数、回测各自独立）。
前端原生 HTML/CSS/JS（零框架、零构建、PWA），后端本地 Python（FastAPI + SQLite + pandas）。

> 工具仅作个人研究，不构成投资建议。所有策略规则都是**待验证的假设**——没通过「回测 → 样本外」检验的规则一律视为无效（需求书 5.1）。

## 快速开始

```bash
pip install -r server/requirements.txt      # Python 3.10+，Windows / macOS / Linux（装在你运行 python 的那个解释器里；启动股票.vbs 用 PATH 上的 python）
python -m server.cli serve --demo           # 合成演示数据（几秒生成，不代表真实行情）→ http://127.0.0.1:8000
```

用真实数据（A 股，BaoStock 免费、无需注册）：

```bash
python -m server.main                       # 启动服务，浏览器打开 http://127.0.0.1:8000（左上角切换 A股 / 美股）
# 然后在「设置」页点「初始化数据」（可先「只拉前 N 只」试跑）；或命令行：
python -m server.cli init --limit 50        # 试跑 50 只
python -m server.cli init                   # 全量：约半天以上（BaoStock 单只 10 年历史约 8~10 秒；先按近 45 天预筛垃圾股再拉 10 年），可随时中断、断点续跑
python -m server.cli update                 # 盘后任务链：更新 → 闸门 → 扫描 → 体检 → 回填 → 事件 → 备份
python -m server.cli init --market US       # 美股（实测）：预筛 5120 只约 1 小时 → 幸存者约 2850 只批量拉 10 年约 20 分钟 → 逐股补行业约 50 分钟（行业未补全不影响扫描），可中断续跑
python -m server.cli update --market US     # 美股盘后任务链
```

Windows 可双击 [启动股票.vbs](启动股票.vbs)（后台拉起服务、打开浏览器、建桌面快捷方式）；`start.bat` 以前台方式运行（`start.bat demo` 为演示数据）。

测试：`python -m pytest -q`（91 条，含「随机游走上策略期望值≈0」的前视泄漏对照实验、成交规则单测、闸门 / 备份 / 限速熔断 / 任务链 / 补跑）。

## 日常流程（需求书 1.7 / 4.2）

1. **盘后**：后端按「市场已收盘 + 上游数据可用」探测并自动跑任务链（应用没开着也没关系——**启动补跑**会按交易日历补缺失的交易日）。
2. **选股**（首页）：看今日观察清单（触发价 / 止损位 / 风险金额 / 建议股数）、数据完整性与市场环境状态 → 「次日执行」复制参数到券商端设条件单。
3. 成交后点「成交了」录入交易（可从清单一键带出形态与理由）→ **持仓**页每日自动**体检**（R 倍数、移动止损位上移、退出信号、时间退出、临近财报）。
4. 平仓后在持仓页看**复盘统计**（形态 × 市场环境 的胜率 / 盈亏比 / 期望 R、实盘 vs 回测）。
5. **回测**页：单因子检验 → 形态事件研究 → 策略回测 → 漏斗消融 → 参数网格。每次结果带 `run_id` / 配置哈希 / 试验次数。

仍有的局限（如实）：
- **A 股盘中实时 / 全市场快照来自东财 push2 网页接口**（直接用 requests，不经 AkShare）：它有 IP 级限流——我在 M0 里连续密集探测后被对端断开了一段时间。系统已降速（2~4 秒/请求、熔断 30 分钟）并在失败时自动降级：L1 走近 45 天预筛、每日增量走 BaoStock 逐只。盘中刷新同样依赖它，可能有延迟。
- **美股免费源没有已退市股票的历史**：美股回测存在幸存者偏差，只作上界参考；真正无偏的证据是 `scan_outcomes`。
- Alpha Vantage / Finnhub 免费档额度很小（约 25 次/天），**没有接入**：事件改用无需密钥且额度充足的 Yahoo + SEC + 巨潮；Alpha Vantage 的新闻情绪分因此没有，`sentiment` 只对业绩预告 / Insider / 关键词公告给出粗略方向。
- 手机经局域网 HTTP 访问只能在线浏览（浏览器限制，需 HTTPS 才能装 PWA / 离线，见需求书 1.6）。

## M0 实测中发现、并已在代码里处理的事项

- **baostock 0.9.4 与 pandas ≥ 2 不兼容**（`ResultSet.get_data()` 调用了已删除的 `DataFrame.append`）→ 数据层改为逐行组装 DataFrame。
- `query_all_stock` 单次约 15~20 秒 → 名单并集改为半年取样、每个日期入库后记录进度，可断点续跑。
- **BaoStock 10 年历史单只约 8~10 秒**（全量约 14 小时）→ 加了 L1 预筛（先拉近 45 天筛价格 / 成交额，只对幸存者拉 10 年）；每日增量只需 1 次请求/只（除权日才补取复权因子），全市场约 1~1.5 小时。
- **AkShare 封装层在本机不可用**（东财接口被断开、新浪每页 ~24 秒）→ 已弃用，改为直接调用东财 push2 / 数据中心接口（`82.push2.eastmoney.com` 节点可用）；失败时 L1 走预筛、增量走 BaoStock；财报日历改用 BaoStock。
- **yfinance 的价格与成交量已按拆股调整**（NVDA 2024-06-05 显示 122.44，真实价 ≈ 1224）→ 必存拆股事件，价格门槛用「还原后的当时价」；拆股后 Yahoo 会把整段历史重新调整，批量增量按重叠日收盘价核对，对不上则整只重拉。
- yfinance `Ticker.news` 在本机返回空，改用 `Search(...).news`。
- BaoStock 日线 `volume` 单位为「股」、`amount` 为「元」；复权因子用 `backAdjustFactor`，与官方 `pctChg` 自洽（抽样 4 只 × 约 2600 日，偏差 > 0.05% 的仅 1 日）。
- 停牌日仍返回一行（`tradeStatus=0`）；系统不填充价格。
- 演示数据的收益来自**合成数据里人为植入的趋势延续**，不代表任何真实规律。

## 默认假设（需求书附录 B，均可在 config.yaml 或设置页修改）

已按你的授权定为默认值（均可改）：
- **费率**（2026-10 核对现行规则）：印花税 0.05% 仅卖出、过户费 0.001% 双向，经手费 + 证管费已含在佣金内；佣金按市场常见的万 2.5（最低 5 元）保守设定，你的券商更低请在设置页下调。
- **备份**：每日备份（个人库 + 扫描 / 回测记录等不可重建数据）写入 `C:/Users/linsh/OneDrive/stock-app-backups`（本机 `data/user_config.yaml` 配置，不入版本库）；行情库全量备份每周一份、只留 3 份，留在本机 `data/backups_full`。
- **检验通过标准**（`config.yaml` 的 `validation`）：单因子——至少 2 个周期同时满足 |IC|≥0.02、|IR|≥0.3、有效 t≥2、分层单调性≥0.8 且方向一致；形态——独立信号日≥50、p≤0.05（对随机入场基线）、按日期望 R>0、95% 置信区间下限>0、正期望年份占比≥60%。通过只是「可评估升格」，仍需样本外确认。
- **财报日历**：弃用 AkShare，改用 BaoStock `query_profit_data` 的实际披露日——存去年同期实际披露日，按去年同期推算今年预计披露日（无记录则用法定截止日）；预计日期额外放宽 3 个交易日。只对「漏斗候选 + 持仓」按需拉取，并带点时的实际披露日用于回测。

其余（L1/L2 阈值、组合约束、市场环境闸门阈值）仍是初始值，应以首次全量运行的剔除统计与回测样本外结果校准。
